# i18n — every text editable from the admin

One source, used by the backend and the frontend, editable at runtime.

```
i18n/translations.csv   key,en,es            ← the source (edit this in git)
        │ compiled into the release (StarterKit.I18n.Reference, @external_resource)
        ▼
translations table      admin edits (edited=true) win   ← StarterKit.I18n.sync/0 on every deploy
        │
        ▼
runtime catalogue       :persistent_term, one flat map per locale (StarterKit.I18n.Catalog)
   ├─ backend: I18n.t/3, put_flash_t, validation errors, emails
   └─ frontend: GET /api/v1/locales/:locale → i18next (flat keys, {{placeholders}})
```

`pnpm i18n:build` writes `i18n/locales/<locale>.json` (flat) for tests and tooling; the app
itself reads the CSV (compiled) and the database.

## Keys

- Dotted namespaces: `settings.members.invite`, `flash.profile.updated`, `mail.invitation.subject`.
- Placeholders `{{name}}` everywhere. Plurals: `key_one` / `key_other` + `count`.
- Validation: a custom message is a key (`validation.email_format`); built-in validations map to
  `validation.<kind>` (`validation.required`, `validation.length_min`, …).
- Emails: `mail.<kind>.subject|body|action`.
- `test/architecture/frontend_test.exs` fails when code uses a static key missing from the CSV,
  and `test/starter_kit/i18n_test.exs` when a locale cell is empty.

## Commands

```
pnpm i18n:build                                   # CSV → i18n/locales/*.json
pnpm i18n:merge new-keys.json                     # add {"ns.key": "English"} entries
OPENROUTER_API_KEY=… pnpm i18n:translate [es]     # fill empty cells through OpenRouter
mix i18n.sync                                     # CSV → dev database (also in mix ecto.setup)
```

## Runtime edits

The superadmin editor reads `GET /api/v1/admin/translations`. It includes every CSV key plus
table-only keys, sorted by key. `q` searches keys and values case-insensitively;
`missing=<locale>` selects empty cells. `page` and `perPage` control pagination; values appear
in CSV locale-column order with each cell's `edited` flag.

`PUT /api/v1/admin/translations/:key` takes flat `{locale, value}` JSON (max 20,000 characters).
URL-encode the key segment. It upserts the cell with `edited = true`, records
`translation.updated`, refreshes the local catalogue before responding and broadcasts a reload
through Phoenix PubSub to every node. Empty edits override CSV text too. The catalogue version
and public locale ETag advance on every successful edit or sync; the same reload version is
broadcast to every node.

`POST /api/v1/admin/translation-fills` takes `{locale}` and fills empty cells through
`StarterKit.AI`/OpenRouter in batches. It returns 201 `{data: {count}, meta: {}}`; filled cells
are edited and audited, including a `translation.filled` summary. Without provider configuration
it returns 503 `ai_not_configured`; provider failures return 503 `ai_unavailable`. The operation
is synchronous. Products with larger catalogues may move it to an Oban job on `default`.

## Deploy sync rules (`StarterKit.I18n.sync/0`, run by `bin/migrate`)

- inserts every `(key, locale)` the CSV has and the table lacks;
- refreshes a row nobody edited when the CSV has a new non-empty value (copy fixes reach production);
- deletes rows nobody edited whose key left the CSV;
- never touches a row an admin edited.

## Locale

API locale precedence: `?locale=` → `Accept-Language` → signed-in user's locale → the first
CSV column. Settings → Profile stores a user's preferred locale; emails use the recipient's locale.

## Client loading

`GET /api/v1/locales/:locale` returns the flat catalogue under `data` and `{locale, version}`
under `meta`. Dictionary keys retain their spelling. Unsupported locales return 404. The strong
ETag is `"<locale>:<version>"`, with `Cache-Control: public, no-cache`. A matching `If-None-Match`
returns an empty 304. The SPA caches the catalogue with React Query; bootstrap's `i18nVersion`
identifies changes after runtime edits or deploy sync. No Inertia props or session cookies are
required for catalogue delivery.

## Adding a locale

1. Add a column to the CSV header (`key,en,es,pt`) and fill it (`pnpm i18n:translate pt`).
2. Add `locale.name.pt` and the locale to `User.locales/0`.
API endpoints need no router change: supported locales come from the CSV columns.
