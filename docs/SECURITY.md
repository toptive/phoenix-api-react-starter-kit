# Security

Reviews are recorded here, newest first. Each review lists **Findings** (confirmed, with an id
and a status: OPEN · IN PROGRESS · FIXED · WON'T FIX · ACCEPTED RISK), a **Watchlist**
(lower confidence) and **Verified safe** areas, so the next review can skip them. A change to the
security surface without a full review is recorded as "Change YYYY-MM-DD".

## Controls in place (the template)

| Area | Control |
|---|---|
| Authorization | One policy per schema, deny by default; `authorize!/3` in every action; `VerifyAuthorized` + architecture test |
| Tenant isolation | Repo tenant guard (`org_id:` / `skip_org_id:`), isolation test per tenant schema |
| Sessions | DB-backed tokens, device list with revoke, password change ends other sessions, sudo mode for sensitive changes, cookie session signed + encrypted, `HttpOnly`, `SameSite=Lax`, every cookie `Secure` in production (`Plugs.SecureCookies`) |
| Client IP | `Plugs.ClientIp`: forwarding headers only from `TRUSTED_PROXY_CIDRS`, `CF-Connecting-IP` only through a Cloudflare edge |
| Sign-in | Magic links single use (15 min) behind a button, no account enumeration, bcrypt, 12-char minimum, rate limits per IP |
| Admin | Superadmin area answers 404 to others; impersonation needs a reason, shows a banner, is audited; superadmins cannot be impersonated |
| Audit | Append-only `audit_events` (DB trigger rejects UPDATE/DELETE); impersonator recorded on every event |
| Browser | CSP with per-request nonce (`script-src 'self' 'nonce-…'`), `frame-ancestors 'none'`, `object-src 'none'`, `base-uri 'self'`, HSTS in production, Referrer-Policy, Permissions-Policy, Phoenix secure headers |
| CSRF | Phoenix `protect_from_forgery` on browser and `/api/v1` (same-origin JSON uses the CSRF token) |
| Uploads | Kind allow-lists, size caps, byte sniffing, no SVG, private objects, short-lived presigned URLs |
| Secrets | Only in the environment (`.kamal/secrets` holds references); dev/test keys regenerated by `bin/rename` |
| Errors | Sentry without request bodies, cookies or PII except the user id |
| Dependencies | `mix deps.audit`, `mix hex.audit`, `pnpm audit --audit-level=high` in every gate |
| Static analysis | `sobelow` in every gate (skips listed below) |

## Change 2026-10-02 — file downloads

The template has no `send_download/3` or `send_file/3`. A product that adds one builds the path
only from allow-listed segments (each matches `\A[A-Za-z0-9_-]+\z`: no separators, dots or glob
characters), expands it, and serves it only when the expanded path starts with the expanded base
directory plus `/`. Test it with hostile values (`../`, `*`, `/`). Sobelow flags the call
(`Traversal.SendDownload`); skip it on that one action, with this reason next to it
(pattern: whvisas `Billing.pack_file/1`).

## Change 2026-10-01 — fixes found by the first products

| Id | Finding | Status |
|---|---|---|
| SEC-1 | `plug RemoteIp` trusted any `X-Forwarded-For`: behind Cloudflare every visitor shared one rate-limit bucket, and anyone could set their audit IP. | FIXED: `Plugs.ClientIp` + `TRUSTED_PROXY_CIDRS` |
| SEC-2 | JSON-LD written raw by Inertia's `<Head>`: a `</script>` in any value closed the tag (XSS). | FIXED: `jsonLdText/1` escapes `<` |
| SEC-3 | Google sign-in linked an existing account by email without Google's `email_verified` claim (account takeover). | FIXED: `upsert_google_user/1` refuses unverified emails |
| SEC-4 | Deleting a user deleted their legal acceptances (the proof of consent). | FIXED: `user_id` nilified, `subject_email_hash` kept |
| SEC-5 | Session, remember-me and `XSRF-TOKEN` cookies had no `Secure` flag. | FIXED: `Plugs.SecureCookies` (`secure_cookies: true` in prod) |
| SEC-6 | The Kamal `pre-build` hook ran `mix check` with the production secrets in its env; a crash could print one. | FIXED: the hook removes every `.kamal/secrets` name |
| SEC-7 | Audit events had no IP unless the caller passed one. | FIXED: the request IP is recorded by default |

## Review 2026-09-30 — template baseline

Scope: the whole template before the first product.

**Findings:** none open.

**Watchlist**
- SEC-W1: git hooks are not a hard gate (`--no-verify`, clones without `mix setup`). Accepted: `/deploy` and the Kamal `pre-build` hook run every gate again.
- SEC-W2: rate limits live in ETS on one node; with several nodes they become per node. Revisit if a product scales out.
- SEC-W3: `Uploads.verify/2` must be called by the context that saves a key; a product that forgets it trusts the browser-declared type. Covered by review, not by a test.

**Verified safe**
- No raw SQL with interpolation; every query goes through Ecto with parameters.
- Magic-link and invitation tokens are stored as SHA-256 hashes; comparison by lookup of the hash.
- Legal document bodies and all user text are rendered as text by React. The only `dangerouslySetInnerHTML` is `components/ui/chart.tsx` (CSS variables built from the chart config, no user input).
- Admin routes are behind `require_superadmin` and each action also authorizes.
